# 沙雕科普动画工作室升级计划

## 目标

把当前单样片、硬编码的 Pillow MVP 升级为“小行星AI观测站”旗下可持续生产“人物对话 + 工程图解”科普视频的引擎。设计资产与渲染代码并行推进，通过稳定契约汇合。

## 分工

| 工作流 | 负责人 | 主要交付 | 不负责 |
| --- | --- | --- | --- |
| 视觉系统 | 反重力 | 品牌、人物、表情、动作关键姿态、场景、背景、道具、图解、motion board、分层资产 | Python 渲染器、Story schema、TTS |
| 引擎与契约 | Codex | Story 版本化、资产 manifest、renderer 接口、布局、动作时间线、镜头系统、跨平台能力 | 决定最终美术风格 |
| 声音与理解 | Codex | MiMo TTS/ASR/视频理解、音频时长、缓存、音画质检 | 角色视觉设计 |
| 联合验收 | 用户 + Codex | 风格选择、10 秒样片、完整样片、质量门槛 | 未验收即批量生产 |

反重力任务书：`docs/ANTIGRAVITY_VISUAL_SYSTEM_REDESIGN_TASK.md`。

母品牌继承简报：`docs/BRAND_INHERITANCE_BRIEF.md`。

## 阶段 0：冻结基线

保留当前样片、封面、关键帧和 MiMo 审片结论，作为升级前对照。基线问题包括人物占位感、动作弱、背景单一、图解重叠、构图裁切和默认音色语速偏快。

完成条件：

- 固定一份 10 秒回归片段。
- 保存 1s、5s、9s 关键帧。
- 建立事实、字幕、音画、布局和视觉重复度检查表。

## 阶段 1：稳定内容与资产契约

Codex 负责：

- 给 Story 增加显式 `schemaVersion`，提供旧 JSON 到新版本的迁移器。
- 将硬编码 `diagram`、`action`、`expression` 字符串变成可验证 registry id。
- 定义品牌、共享、领域包的独立 manifest，以及 `design-assets.json` catalog、锚点、variants 和能力声明。
- 区分内容语义与渲染提示，保持 Story 可供 Pillow、Revideo、Motion Canvas 或其他 renderer 复用。
- 增加 Story/asset lint：未知动作、缺失锚点、重复 id、越界坐标、缺失文件必须在渲染前失败。

完成条件：旧样例自动迁移，新样例验证通过，缺失资产有明确报错。

## 阶段 2：渲染器组件化

Codex 负责建立接口：

- `CharacterRenderer`：procedural、SVG sprite、PNG pose pack。
- `BackgroundRenderer`：分层背景、色彩变体、景深顺序。
- `DiagramRenderer`：流程图、对比卡、时间线、图表、公式和设备示意。
- `SubtitleRenderer`：自适应换行、安全区、说话人标签、强调词。
- `LayoutEngine`：16:9、9:16、人物数量、图解占比和字幕高度约束。
- `CameraController`：静止、推近、拉远、平移、跟随和切镜。

现有 `Studio` 将退化为组合器，不再直接包含所有人物和图解绘制逻辑。

完成条件：替换人物资产或背景不需要修改 Story 和组合器。

## 阶段 3：动作与表演系统

Codex 根据反重力 motion spec 实现：

- 动作片段的 anticipation、action、settle。
- 动作混合与互斥，例如 talk + point、walk + look-at。
- 眨眼、呼吸、嘴型和视线等低频自动行为。
- 角色锚点、道具挂接、左右朝向和镜像规则。
- 镜头级入场、退出、遮挡转场和强调节奏。

完成条件：动作可通过 Story 参数驱动，同一动作在不同角色上具有一致语义和角色化差异。

## 阶段 4：声音导演与音画同步

MiMo 基础能力已接入。下一步由 Codex 完成：

- 为角色定义 voice profile、情绪、语速和发音词典。
- TTS 先生成、真实时长后解析，禁止通过波形压缩硬塞进镜头。
- ASR 回读与原文对齐，标记漏字、错读、术语拼读和异常停顿。
- 根据 resolved timeline 驱动嘴型、字幕和镜头切换。
- 对完整音轨和分镜分别做音频理解质检。

完成条件：关键术语 ASR 对齐达标，对白无截断、无重叠，字幕和镜头边界跟随真实声音。

## 阶段 5：自动布局与多比例

Codex 负责：

- 约束式布局，禁止人物、标题、图解和字幕互相覆盖。
- 文字测量、动态字号、最大行数和溢出失败策略。
- 横屏与竖屏分别重排，不做中心裁切冒充适配。
- 图解密度和角色占屏比例检查。

完成条件：代表镜头在 960×540、1920×1080、1080×1920 下均通过安全区和可读性检查。

## 阶段 6：评测与生产化

Codex 负责：

- `doctor` 命令：FFmpeg、字体、MiMo、Story、资产完整性。
- golden PNG 视觉回归测试和允许差异阈值。
- MiMo 视频理解审片：字幕、画面、节奏、音画、事实表达。
- 缓存、增量渲染、失败续跑和构建 manifest。
- macOS、Windows、Linux 路径与进程兼容。

完成条件：一次命令可验证、构建、审片并输出结构化报告。

## 汇合门槛

反重力设计资产进入代码前必须满足：

- 有可解析的资产 manifest。
- SVG/PNG 无远程依赖、无字体文件、无硬编码对白。
- 人物具有标准锚点，背景具有稳定层级，动作具有关键姿态。
- 16:9 与 9:16 均提供构图依据。
- 前 10 秒 style frame 和 motion board 已通过用户方向确认。

Codex 引擎接入完整样片前必须满足：

- Story 和资产 schema 均有版本。
- 旧样例可迁移。
- 单元测试、视觉回归和 10 秒人工抽查通过。
- 不依赖特定单集的硬编码标题、道具或图解。

## 推荐执行顺序

1. 反重力先完成审计、三个设计方向和推荐方向。
2. Codex 同步完成 Story v2、资产 manifest schema 与 renderer 接口骨架。
3. 用户确认方向后，反重力产出完整资产包。
4. Codex 接入两个人物、一个背景和前三个镜头，生成 10 秒技术样片。
5. 联合验收后再扩展八镜头和 9:16，避免在错误方向上批量制作。
